# End-to-end tests with real input / End-to-End-Tests mit echter Eingabe

English first, Deutsch darunter.

## English

These tests start the **real app** and operate it through the W3C WebDriver
**Actions** API (pointer and keyboard events delivered by the browser engine
itself). They exist because several bugs only showed up with a real mouse or
keyboard in a real window - for example the "Edit" button in the Printer Manager
that saved and closed its form with the same click, which a script-driven
`element.click()` never reproduced - and because layout bugs (clipped text,
overlaps, jumping elements) were only found by people on test VMs.

Stack: `tauri-driver` (Tauri's WebDriver proxy) + WebdriverIO (Mocha, TypeScript).
Linux uses `WebKitWebDriver` (package `webkit2gtk-driver`), Windows uses
`msedgedriver` matching the installed WebView2 runtime.

### What is tested

| Spec | Checks | Linux | Windows (CI subset) |
| --- | --- | --- | --- |
| `01-start` | window appears, header visible, no error dialog, native window title | yes | yes (title check skipped) |
| `02-catalog` | seeded catalog shows 8 cards and "8 Dateien" | yes | no |
| `03-context-menu` | real right click menu, rename with keyboard (card and file on disk) | yes | no |
| `04-printer-manager` | "Bearbeiten" keeps the form open (regression), nozzle validation, valid save | yes | yes |
| `05-drag` | mouse drag of a card to a folder (file moves on disk) and to a collection | yes | no |
| `06-plates` | plate bar below the 3D view, click / arrow keys / Home / End, `aria-checked` | yes | no |
| `07-layout-audit` | at 900, 1000, 1280 px: no truncated key labels, one-line header with help icon inside the window, no horizontal document scroll, no overlap of plate bar and 3D controls; for catalog, Printer Manager, Material Manager, settings tabs and the detail page | yes | yes |
| `08-typography` | every visible text uses Barlow (IBM Plex Mono only in `.font-code`), none of the glyphs that must be icons is rendered as text | yes | no |

Only Linux: `01` native title (X server query), and all specs that depend on
WebGL rendering of the 3D view, on the drag/rename details or on being
verified on Linux first (`02`, `03`, `05`, `06`, `08`). They use nothing
Linux-specific in principle and can be added to the Windows subset
(`test:windows` in `package.json`) once the Windows job has run green.

### How the tests get their data

Each spec file gets a **fresh throw-away `HOME`/`XDG_*`**; the real catalog is
never touched. The database is created by the app itself (it is launched once
to produce a template `out/template/catalog.db`), then filled with SQL:
folders, 8 models, a collection, a printer and two spools. The model files are
generated by `fixtures/make-fixtures.mjs` (deterministic ASCII STL, a coloured
3MF, the three-plate 3MF from `src-tauri/tests/fixtures/`; also an archive and
a broken STL in `Extras/`, not used by a test yet because importing needs a
native file dialog that WebDriver cannot operate).

The app cannot be launched twice (single instance via D-Bus), so spec files
run one after the other and the harness waits until the previous instance is
gone. **No change to the app was needed**: the catalog is prepared on disk and
in `localStorage` (set through WebDriver, then reload).

Windows caveat: Windows resolves `%APPDATA%` from the registry, not from
environment variables, so the isolation by `HOME` does not work there. The
harness therefore refuses to run on Windows unless `CI=true` (or
`MFK_E2E_ALLOW_REAL_PROFILE=1`) and wipes the app's data folders before each
file. Never run it on a machine with a real catalog.

### Run locally (Docker, Ubuntu 24.04 like the GitHub runner)

```bash
# 1. get an app to test: the extracted release AppImage ...
./"3MF Katalog Manager Preview_0.16.0-3_amd64.AppImage" --appimage-extract   # creates squashfs-root/
# 2. install the test dependencies once
npm ci --prefix e2e
# 3. run everything (builds the image mfk-e2e-ubuntu2404 on first use)
MFK_E2E_APPDIR=$PWD/squashfs-root e2e/run-docker.sh
# a single spec
MFK_E2E_APPDIR=$PWD/squashfs-root e2e/run-docker.sh -- --spec specs/04-printer-manager.e2e.ts
```

Failures leave screenshots in `e2e/out/screenshots/` and the app's own log in
`e2e/out/app-logs/`. `e2e/out/` is git-ignored.

Without Docker on a Linux machine with a display: install `webkit2gtk-driver`,
`xvfb`, `openbox`, `dbus-x11`, `cargo install tauri-driver --locked`, then
`MFK_E2E_APP=/path/to/app e2e/docker/entrypoint.sh npm test --prefix e2e`.
`MFK_E2E_APP` is the executable (for an extracted AppImage use its `AppRun`).

### CI

`.github/workflows/e2e.yml` runs on `workflow_dispatch` and on pull requests
that touch `src/**`, `src-tauri/**` or `e2e/**`:

- **Linux** (`ubuntu-24.04`): builds the app in debug mode without STEP
  (`tauri build --debug --no-bundle -- --no-default-features`), installs
  `tauri-driver` (cached), runs all specs under `xvfb` + `dbus-run-session` +
  `openbox`, uploads screenshots on failure.
- **Windows** (`windows-2022`): installs the `msedgedriver` that matches the
  WebView2 runtime (`e2e/scripts/install-msedgedriver.ps1`), builds, runs the
  Windows subset. **This job is `continue-on-error` and has never run on a real
  runner**; remove `continue-on-error` after the first green run.

### Layout and font audits: allowlist

`layout-allowlist.json` lists elements that are allowed to be truncated or to use
other fonts/glyphs, each with a reason. The loader rejects entries without a
reason. Keep it short: a new entry means "this truncation is intentional".

### Known limits of the harness

- WebKitWebDriver reports `""` from `getText()` for text in an ellipsis-clipped
  box; the specs read `textContent` there.
- Upper-case letters sent as plain keys arrive in lower case (shift is not
  applied); tests type lower-case text.
- Without a window manager the webview reports a 0x0 viewport; the image ships
  `openbox`.

## Deutsch

Diese Tests starten die **echte App** und bedienen sie über die W3C-WebDriver-
**Actions** (Zeiger- und Tastaturereignisse, die die Browser-Engine selbst
erzeugt). Anlass: Mehrere Fehler traten nur mit echter Maus/Tastatur im echten
Fenster auf (zum Beispiel der Knopf „Bearbeiten“ im Printer Manager, der mit
demselben Klick speicherte und das Formular schloss; ein Skript-`click()`
zeigte das nie), und Layoutfehler (abgeschnittene Texte, Überlagerungen,
springende Elemente) fanden bisher nur Menschen auf Test-VMs.

Technik: `tauri-driver` + WebdriverIO (Mocha, TypeScript). Linux:
`WebKitWebDriver` (`webkit2gtk-driver`), Windows: `msedgedriver` passend zur
installierten WebView2-Laufzeit.

### Was getestet wird

Siehe die Tabelle oben (`01` bis `08`). Nur Linux sind: der native Fenstertitel
in `01` (Abfrage beim X-Server) sowie `02`, `03`, `05`, `06` und `08`; sie
brauchen im Prinzip nichts Linux-Spezifisches und können in die Windows-Auswahl
(`test:windows` in `package.json`) wandern, sobald der Windows-Job einmal grün
lief. Windows-Auswahl in CI: `01`, `04`, `07`.

### Testdaten

Jede Testdatei bekommt ein **frisches Wegwerf-`HOME`/`XDG_*`**, der echte
Katalog wird nie berührt. Die Datenbank erzeugt die App selbst (einmal starten,
Ergebnis als Vorlage `out/template/catalog.db`), danach werden per SQL Ordner,
8 Modelle, eine Sammlung, ein Drucker und zwei Spulen eingetragen. Die
Modelldateien erzeugt `fixtures/make-fixtures.mjs` deterministisch (ASCII-STL,
farbige 3MF, die Dreiplatten-3MF aus `src-tauri/tests/fixtures/`; dazu ein
Archiv und ein kaputtes STL in `Extras/`, noch von keinem Test genutzt, weil der
Import einen nativen Dateidialog braucht, den WebDriver nicht bedienen kann).

Die App lässt sich nur einmal starten (Einzelinstanz per D-Bus): die Dateien
laufen nacheinander, der Aufbau wartet, bis die vorige Instanz beendet ist.
**An der App war keine Änderung nötig**: der Katalog wird auf der Platte und in
`localStorage` vorbereitet (per WebDriver gesetzt, dann neu geladen).

Windows-Vorbehalt: Windows ermittelt `%APPDATA%` aus der Registry, nicht aus
Umgebungsvariablen; die Isolierung über `HOME` greift dort nicht. Der Aufbau
verweigert deshalb den Lauf unter Windows ohne `CI=true` (oder
`MFK_E2E_ALLOW_REAL_PROFILE=1`) und löscht vor jeder Datei die Datenordner der
App. Niemals auf einem Rechner mit echtem Katalog starten.

### Lokal starten (Docker, Ubuntu 24.04 wie der GitHub-Runner)

Befehle siehe oben (Abschnitt „Run locally“). Fehlschläge hinterlassen
Screenshots in `e2e/out/screenshots/` und das App-Log in `e2e/out/app-logs/`;
`e2e/out/` ist in Git ausgenommen.

### CI

`.github/workflows/e2e.yml`: `workflow_dispatch` und Pull Requests, die `src/**`,
`src-tauri/**` oder `e2e/**` ändern. Linux baut die App im Debug-Modus ohne
STEP und führt alle Tests unter `xvfb` aus; Windows installiert den passenden
`msedgedriver` und führt die Windows-Auswahl aus. **Der Windows-Job ist
`continue-on-error` und lief noch nie auf einem echten Runner**; nach dem ersten
grünen Lauf `continue-on-error` entfernen.

### Positivliste für Layout und Schriften

`layout-allowlist.json` nennt Elemente, die absichtlich abgeschnitten sein oder
andere Schriften/Zeichen haben dürfen, jeweils mit Begründung (Einträge ohne
Begründung werden abgelehnt). Kurz halten: ein neuer Eintrag heißt „diese
Kürzung ist gewollt“.

### Bekannte Grenzen des Aufbaus

- WebKitWebDriver liefert bei Text in einer Ellipsen-Box `""` aus `getText()`;
  die Tests lesen dort `textContent`.
- Großbuchstaben als einfache Tasten kommen klein an (Umschalt wird nicht
  angewendet); Tests tippen Kleinbuchstaben.
- Ohne Fenstermanager meldet die WebView 0x0; das Image bringt `openbox` mit.
